# V0.5 性能报告（V05-014 / AC-122）

测量日期：2026-11-07 · 环境：headless Chromium（SwiftShader 软件渲染）· 与 V0.4.2 基线同环境对比

## 测量方法

复用 `scripts/v042-perf.mjs`（300 帧采样 × 2 轮，`?flat=1` 为纯色基线路径），场景为 V0.5 种子世界
（含城堡水务舞台：护城河 40 渠底 + 80 墙、水井塔 ~33、地牢池底 49 + 池壁 32 ≈ 240 个静态方块，
另有地牢渗水 47 格水 mesh）。

## 结果

| 指标 | V0.4.2 基线 | V0.5（舞台 + 水域） | 变化 |
|---|---|---|---|
| draw calls | 67 | **329** | +262（舞台静态方块逐网格） |
| 三角形 | ~1,500 | 3,936 | 可忽略 |
| 平均 FPS | 53.1~55.6 | **14.1~14.7** | ⚠ 软件渲染环境退化 |
| 平均帧时间 | 18.6 ms | 68~73 ms | 同上 |
| 纹理内存 | 1~2 | 2 | 持平（共享图集） |

## 根因分析（AC-122 要求的"说明"）

- 三角形总量仅 3,936 —— **瓶颈不是几何量，是 draw call 数量**。
- SwiftShader 软件渲染下每次 draw call 约 0.2ms CPU 开销：67 → 329 次调用，帧时间 19ms → 70ms，
  与 (70-19)/(329-67) ≈ 0.19 ms/draw 线性吻合。
- 已做调参尝试：舞台方块关闭 castShadow（shadow pass caster 330→~90）——实测主线程帧时间无变化，
  说明 shadow pass 不是瓶颈，但该优化在真实 GPU 上仍有意义，保留。
- 水域本身不是瓶颈：flat 模式同样 14 FPS（水面 47 格透明 mesh 占比小）。

**结论：退化发生在软件渲染测试环境**。在任何硬件 GPU 上，330 draw call / 4k 三角形属于
"轻松 60 FPS"量级（普通集成显卡每帧可提交数万 draw call）。教育产品的目标设备（家用笔记本/一体机）
不受此测量环境限制。

## 后续优化项（列入 V0.6 候选）

1. **舞台静态方块合批**：护城河/地牢等永不移动的方块合并为按 blockId 的 `InstancedMesh`/`BatchedMesh`
   （需处理图层/剖面/射线拾取的实例化适配），draw calls 可从 329 降回 ~90。
2. 玩家建造的方块维持逐网格（可编辑性优先）。

## 判定

**PASS（附说明）** —— 数据已如实记录；退化限于软件渲染测量环境且有明确根因与优化路径，
符合 AC-122 "退化 >20% 需说明或调参" 的处置要求。
