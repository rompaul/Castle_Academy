# ADR-0004: V0.4 Layer & Section Architecture (Underground Infrastructure)

**Status:** Accepted  
**Date:** 2026-11-06  
**Decision owner:** Product/Engineering owner  
**Related documents/issues:** ADR-0001 (3D Engine Selection), ADR-0002 (World Persistence Format), ADR-0003 (V0.3 Building Tools), COORDINATE_CALLSITE_AUDIT (V04-003), Product Master Plan (V0.4 = Underground infrastructure)

## Context

V0.4 delivers "Underground infrastructure" per the Product Master Plan roadmap (`00_Product_Master_Plan/README.md:57`). This requires:

1. **Negative Y support** — blocks can be placed below y=0 (underground/b basement).
2. **Layer organization** — blocks grouped into visual/organizational layers by Y range (ground, upper floors, basement, foundation, passage).
3. **Section view** — cut the world along an axis plane to inspect interior structure.

A decision is needed on how layers and sections are modeled without violating the plugin-first architecture, without adding a second source of truth for block data, and without bloating the renderer.

## Decision drivers

- **WorldState remains the single source of truth** (`CA-TECH-003:75`, `CA-TECH-001:73-74`). Layers/sections are view/organization dimensions, not a parallel block database.
- **Plugin boundaries** — every executable feature is a standalone plugin (`CA-TECH-001:22-24`). Plugins depend only on Core public interfaces (`WorldState`, `EventBus`).
- **No personal data** — layer/section state contains only IDs, booleans, and integers (`CA-TECH-005:9-11`).
- **Testability** — layer rules are pure functions; each plugin/module has unit tests (`CA-TECH-004:6`).
- **Backward compatibility** — V0.2 persistence schema version 1 must keep loading; new layer/section state is view-only and not persisted in the world snapshot.

## Decision

**Option A: Layer + Section as view-state plugins, WorldState unchanged for block data.**

### 1. World bounds (coordinates.ts)

`WORLD_BOUNDS` centralized in `src/core/world/coordinates.ts`:
- X/Z: `[-16, 16)` (unchanged from V0.1/V0.3)
- Y: `[-32, 64)` (extended to support negative Y / underground)

`isInsideBuildArea` uses `WORLD_BOUNDS` instead of hardcoded `y >= 0 && y < 64`.

### 2. Layer model (LayerTypes.ts / LayerRegistry.ts / LayerPlugin.ts / LayerRules.ts)

- `LayerDefinition`: `{ id, label, kind, minY, maxYExclusive, order, defaultVisible, buildable }`
- `LayerKind`: `ground-floor | upper-floor | basement | foundation | passage`
- `ViewMode`: `all | above-ground | underground | current-layer | custom`
- `LayerState`: `{ activeLayerId, visibilityByLayer, viewMode, section }`
- `LayerRegistry`: enforces unique IDs, non-overlapping Y ranges, valid minY < maxYExclusive, at least one default layer.
- `LayerRules`: pure functions for `resolveLayerId(y)`, `isLayerVisible`, `isPositionVisible`, `getVisibleLayerIds`.
- `LayerPlugin`: facade over registry + EventBus. Emits `layer.visibility.changed`, `view.mode.changed`, `section.view.changed`. Exposes `onViewModeChange`/`onSectionChange` for UI subscription.

Default layers registered in `ThreeWorldRenderer` when no external `LayerPlugin` is injected:
- `basement-1`: Y [-4, 0), kind basement, order -1
- `ground`: Y [0, 4), kind ground-floor, order 0
- `level-1`: Y [4, 8), kind upper-floor, order 1

### 3. Section model (LayerTypes.ts / LayerPlugin.ts)

- `SectionAxis`: `"x" | "y" | "z"` (extended from original x/z to include y)
- `SectionKeptSide`: `"positive" | "negative"`
- `SectionViewState`: `{ enabled, axis, coordinate, keptSide }`
- `LayerPlugin.setSectionView(partial)` merges and emits `section.view.changed`.

### 4. Rendering (ThreeWorldRenderer.ts / LayerRenderAdapter.ts)

- `LayerRenderAdapter`: maps `layerId` → Three.js `Group`. Blocks added/removed via `addMeshToLayer`/`removeMeshFromLayer`. Visibility applied via `group.visible`.
- `ThreeWorldRenderer`:
  - Constructor accepts optional `LayerPlugin`/`LayerRenderAdapter` (created internally if not provided).
  - `addBlock`/`removeBlock`/`reloadFromWorld` route meshes through `LayerRenderAdapter` and record `mesh.userData.layerId`.
  - Subscribes to `layer.visibility.changed`, `view.mode.changed`, `section.view.changed` to update `mesh.visible`.
  - Raycast/intersection filters out meshes on layers that are not effectively visible (hidden layers cannot be selected/removed).
  - `applySectionView(section)`: for each block mesh, computes `keep` based on `axis`/`coordinate`/`keptSide`; sets `mesh.visible`; clears outline/target if current target is hidden.
  - `dispose` unsubscribes all layer/section event listeners.

### 5. UI (App.tsx / styles.css)

- Layers panel opened from topbar "Layers" button.
- **Layers**: two icon buttons — Ground (Home) / Underground (ArrowDown). Independent checkboxes, both can be selected simultaneously. Ground controls all layers with `minY >= 0`; Underground controls all layers with `maxYExclusive <= 0`.
- **Section**: Enabled checkbox + Axis X/Y/Z icon buttons (ArrowRight/ArrowUp/ArrowLeft, single select) + coordinate number input + Keep +/- checkboxes.
- Icon active state driven by React state subscribed to LayerPlugin events (`onViewModeChange`/`onSectionChange`).

## Rationale

- Keeping WorldState as the single source of truth avoids data duplication and sync bugs; layers/sections are derived view state.
- Pure LayerRules functions are easy to unit-test in isolation (no Three.js/DOM dependency).
- EventBus-driven UI subscription keeps React and Three.js loosely coupled; renderer updates react to plugin state changes without direct imports.
- Extending `SectionAxis` to include Y supports horizontal section cuts (e.g., slice at a specific height), matching the "underground infrastructure" theme.

## Consequences

### Positive
- Underground blocks can be placed, rendered, collided, and raycast-tested.
- Layer visibility toggles update Three.js Groups without rebuilding WorldState.
- Section view reveals interior structure for teaching/inspection.
- All new modules are unit-tested (14 files / 109 tests passing).

### Negative / trade-offs
- Layer/section view state is not persisted in V0.2 world snapshot (view-only). Cross-session layer/section preferences require a future persistence extension.
- Default layers cover Y [-4, 8); blocks outside this range fall back to the default layer. More layer definitions may be needed for deeper underground (down to -32).

### Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| Blocks outside default layer ranges lack a dedicated layer | Falls back to default layer; review layer coverage if deeper basement used |
| View state lost on refresh | Acceptable for V0.4; persistence extension in V0.4+ |
| Section coordinate out of world bounds | No hard clamp; keep logic still works (may hide all blocks). UI could add min/max hints. |

## Follow-up actions

- [ ] Persist layer/section view state across sessions (V0.4+ persistence extension)
- [ ] Add more layer definitions for deeper underground (Y down to -32)
- [ ] E2E Playwright test for layer visibility + section view round-trip
