# Castle Academy V0.1.1 — Stability Repair & Verification Notes

Date: 2026-11-05

## Repair scope

This is a stability repair of the V0.1 source, not a feature expansion.

### Fixed in source

- Added finite-integer validation for voxel coordinates and enforced it at the `WorldState` boundary.
- Added runtime validation for block IDs before insertion.
- Implemented player-vs-voxel collision using a horizontal circle / vertical body interval. Horizontal movement is resolved per axis to permit wall sliding; vertical creative flight is retained but cannot pass through solid voxels.
- Moved pointer-lock initiation to the direct Enter World click path; retained canvas-click retry and added rejection/error messaging.
- Fixed React ref typing by importing `MutableRefObject` as a type.
- Added Node type dependency and scoped Node types to the tooling TypeScript project.
- Added deterministic EventBus unsubscribe behavior and a fallback event ID for environments without `crypto.randomUUID`.
- Added disposal for ground, grid, outline, shared geometry/material resources; reset clears stale target/outline state.
- Added WebGL initialization error messaging and a development-only test bridge.
- Added source import/dependency/script verification, five unit-test files, and four browser E2E tests covering startup, world-state operations, keyboard movement, collision, and hotbar selection.
- Added Node/npm engine requirements and documented the verification commands.

## Important limitations

- No `package-lock.json` is included because npm could not reach/complete dependency resolution in this environment. Run `npm install` once on the target machine to generate it; commit that lockfile, then use `npm ci` for repeatable installs thereafter.
- The player controller is a lightweight collision approximation, not a full rigid-body physics engine. Creative vertical flight remains part of V0.1.
- The development-only `window.__CASTLE_TEST__` bridge is guarded by `import.meta.env.DEV`; it is not included in production builds.
- This package is a repaired source candidate, not a dynamically verified release. Do not label it fully accepted until the commands below pass on the target Windows 11 machine.

## Target-machine verification

From the project root in PowerShell:

```powershell
node --version
npm --version
npm install
npm run verify:source
npm run typecheck
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

Expected: every command exits with code 0. Then run `npm run dev`, open the local URL in Chrome or Edge, and manually verify pointer lock, WASD, vertical flight, collision against walls, block placement/removal, number-key hotbar selection, and reset.

After the first successful `npm install`, retain `package-lock.json` and switch future clean installs to `npm ci`.
