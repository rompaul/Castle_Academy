# V0.51 性能报告（V51-018）

**测量日期：** 2026-11-10 · **源码 HEAD：** `72eb773`（V51-017 完成态，`package.json` 仍为 `0.5.0`）
**对照基线：** `6f5e244`（v0.5.0 发布 commit，`git archive` 导出至临时目录）
**环境：** headless Chromium / SwiftShader 软件渲染，1280×720，Windows 本机

---

## 1. 判定口径（D-2）

执行包《V0.51_Acceptance_Test_Plan》§4 引用「V0.5 基线 53 FPS / 67 draw calls / 18.6ms」。该数字来自 V0.4.2 时期另一套环境，与本机软件渲染实测不符；基线审计 `V0.51_REPOSITORY_BASELINE.md` §5 已登记 **D-2**：

> 绝对阈值不可直接套用 → 性能判定改为**同机、同脚本对照本次基线**，帧时间回退 ≤5%，报告注明两次口径差异。

本次进一步观察到绝对帧率随宿主负载漂移：V51-002 会话实测 `21.2 FPS / 47.06ms / 329 dc`，本会话实测 `16.1~16.6 FPS / 60~62ms / 329 dc`。因此：

- **判定依据**：同一次会话内 A/B 配对对照的**相对帧时间差**与 **draw calls 变化**；
- **仅作记录、不作阈值**：绝对 FPS / 帧时间；
- 其余指标按 §4 原始阈值判定：侧栏展开/折叠 `<50ms`、档案读写同步 `<16ms`。

---

## 2. 测量方法

| 项 | 说明 |
|----|------|
| 渲染 A/B | `scripts/v042-perf.mjs`，300 帧/模式，每轮含 `?flat=1`、`textured`、`textured(run2)`；取该轮两次 `textured` 的帧时间均值 |
| DOM / 档案 | `scripts/v051-perf.mjs`，20 次侧栏开合、20 次档案写、`20 × 100` 次档案读（按批摊到单次）；`MutationObserver` 量 React state → `data-open` DOM 提交耗时 |
| 基线服务 | `git archive 6f5e244` → `.perf-baseline`，`npx vite .perf-baseline --port 5188 --strictPort --host 127.0.0.1` |
| 当前服务 | 工作树源码，`npx vite --port 5173 --strictPort --host 127.0.0.1` |
| 顺序 | **ABBA** 抵消热漂移：`baseline R1 → current R1 → current R2 → baseline R2`；另做一次「仅 5173 存活」的隔离复测 |
| 计时精度 | 页面内 `performance.now()` 实测分辨率 **0.1ms**；单次档案读取低于该分辨率，故按 100 次批量测量后摊销 |

> 注：`npx vite --root ...` 在本机 Vite 版本会报 `CACError: Unknown option --root`，须用位置参数 `npx vite .perf-baseline ...`。

### 3.2 配对结论

| 对照 | V0.5 基线 | V0.51 当前 | 帧时间差 | 判定 |
|------|-----------|-----------|----------|------|
| 第 1 组（baseline R1 → current R1） | 60.435 ms | 60.950 ms | **+0.85%** | 通过 |
| 第 2 组（current R2 → baseline R2，反序） | 62.130 ms | 61.770 ms | **−0.58%**（V0.51 略快） | 通过 |
| 四轮 `textured` 汇总 | **61.28 ms**（16.32 FPS） | **61.36 ms**（16.30 FPS） | **+0.13%** | 通过 |
| draw calls | 329 | 329 | **0** | 通过 |
| 三角形 / 纹理内存 | 3936 / 2 | 3936 / 2 | 0 | 通过 |

**相对基线帧时间回退 +0.13%，远优于 ≤5% 阈值；draw calls 无增加。** 任务侧栏、引导卡片、详情面板、奖励卡均为 DOM overlay，未进入 Three.js render pass，与 §4「UI 为 DOM overlay，不进 render pass」假设一致。

隔离复测（关闭 5188 后）当前源码仍为 16.4~16.6 FPS，与 A/B 中的当前值一致，说明绝对帧率下降来自**宿主机整体负载漂移**，而非两服务共存或 V0.51 改动。

## 4. DOM 交互 / 档案读写结果

`missions = 15`、`drawCalls = 329`（由 `window.__CASTLE_TEST__` 读取）。

| 指标 | 阈值 | 稳态 avg | 观测最差 max | p95 范围 | 判定 |
|------|------|----------|--------------|----------|------|
| 侧栏展开 | <50ms | 1.4~3.2 ms | **31.6 ms** | 7.4~31.6 ms | ✅ |
| 侧栏收起 | <50ms | 0.39~1.37 ms | **17.9 ms** | 0.8~17.9 ms | ✅ |
| 档案写（`createProfile` → localStorage） | <16ms | 0.245~0.30 ms | **1.6 ms** | 0.8~1.6 ms | ✅ |
| 档案读（`snapshot` + `listProfiles`） | <16ms | 0.005~0.006 ms | **0.024 ms** | 0.013~0.024 ms | ✅ |

三轮有效采样（R2/R3/R4，各 20 次）。说明两点：

1. **每轮出现 1 次 7.6~31.6ms 的孤立峰值**，属浏览器 GC / 渲染调度抖动，非冷启动：R4 单独记录 `sidebarOpenColdMs = 7.6`，去掉首次后的稳态 19 次样本 avg `2.189ms` / max `7.4ms`。峰值仍全部低于 50ms 阈值。
2. 初版脚本单次读取被 `performance.now()` 的 0.1ms 精度截断为 `0.00ms`；改为 100 次批量摊销后得到真实的 `0.005~0.006ms`，脚本已同步记录 `timerResolutionMs` 与 `readBatchSize` 以便复核。

## 5. 判定

**PASS —— V0.51 相对 V0.5 基线无性能回退。**

| 验收项 | 阈值 | 实测 | 结论 |
|--------|------|------|------|
| 世界视图 FPS / 帧时间 | 相对基线回退 ≤5% | +0.13% | PASS |
| draw calls | 不增加 | 329 → 329 | PASS |
| 侧栏展开/折叠 | <50ms | 最差 31.6ms / 17.9ms | PASS |
| 档案读写 | <16ms | 最差 1.6ms / 0.024ms | PASS |

在 15 个任务、任务侧栏、首次进入引导、提示阶梯、奖励队列、交流类文字证据全部接入的情况下，渲染与交互均无回退。

## 6. 已知限制与开放项（不阻断本阶段）

- **绝对 FPS 偏低（~16.5）是 V0.5 既有问题**，源头为种子世界舞台静态方块逐网格导致的 329 draw calls，已在 `docs/v0.5/V0.5_Performance_Report.md`（AC-122）归因于 SwiftShader 软件渲染；硬件 GPU 上非瓶颈。**非 V0.51 引入**。
- V0.6 优化候选不变：舞台静态方块改 `InstancedMesh` / `BatchedMesh`，draw calls 可回落至 ~90。
- **绝对帧率跨会话漂移**（V51-002 为 21.2 FPS，本会话 16.5 FPS）。建议 V0.6 建立固定机器 / 固定负载的基线采集规程，避免再次出现「文档基线数字与实测不符」（D-2 的成因）。
- D-1（`styles.css` 既有 Google Fonts 外链）本版未改动，对帧时间无可观测影响，留 V0.6 独立 DDR 处理。
- 本报告仅覆盖性能；**不能替代 V51-019 / STOP GATE-3 发布签核**。
