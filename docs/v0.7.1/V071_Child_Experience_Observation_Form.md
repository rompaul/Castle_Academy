# V0.7.1 儿童体验观察记录表

**目的：** 验证「场景化设计计算」是否真的融进修桥任务，而不是变成一张数学练习卷。
**对象：** 修复王国旧桥完整流程（故事 → 局部地图 → 测量 → 设计 → 验证 → 施工 → 奖励预告）。
**注意：** 本表只记观察结论，不记录儿童真实姓名、学校、联系方式或自由文本反思到任何存档。

## 1. 测试安排

| 项 | 建议 |
|---|---|
| 人数 | 每个年龄段至少 1 人；条件允许时每段 2–3 人 |
| 年龄段 | 6–8 岁、9–12 岁、13–15 岁 |
| 时长 | 每人 12–15 分钟 |
| 场地 | 桌面浏览器，1280×720 或更大；提前确认 WebGL 可用 |
| 开始前 | **不提前讲解操作步骤**，只说「城堡的桥坏了，你试试看怎么修」 |
| 可帮助 | 孩子主动求助时，按 H1→H4 逐级给提示，记录触发到哪一级 |
| 观察者 | 1 人主持、1 人记录；只记录行为与原话，不代孩子操作 |

## 3. 结束后访谈（开放式，不追问标准答案）

1. 「你刚才为什么把桥做成这个长度和宽度？」
2. 「你觉得刚才是在做数学题，还是在修一座桥？为什么？」
3. 「如果还能继续，你最想做什么？」

把第 2 题的原话原样记下——这是判断 V0.7.1 体验是否通过的关键信号。

## 4. 通过门槛（规格 §15.4）

首次体验重点确认：

- [ ] 孩子能从故事理解工程目标。
- [ ] 能在轻量提示下完成设计。
- [ ] 能说出设计参数怎样影响最后的桥。
- [ ] 至少一部分孩子主动表达「想看看桥建出来是什么样」或类似意思。
- [ ] 资源解锁让孩子明白下一项工程的用途。

**失败信号：** 如果多数孩子把设计阶段描述成「做数学题」，即使技术验收全绿，也不能认为 V0.7.1 体验验证通过。
