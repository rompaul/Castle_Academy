## 5. Reuse vs. Extension Points for V0.4.2

| Aspect | Current State | V0.4.2 Action |
|--------|--------------|---------------|
| Block ID registry | `blocks.ts` array of 7 | **Extend minimally**: add new IDs only for blocks that are logically distinct. Reuse existing IDs where color/role matches. |
| Block material | `MeshStandardMaterial` per ID, color only | **Extend**: add texture maps (top/side/bottom) per block ID; keep shared geometry/material reuse. |
| Block model | Single `BoxGeometry(1,1,1)` for all | **Extend**: add `BlockModel` type (cube/slab/stair/pillar/arch/frame) with collision/raycast shape metadata. |
| WorldState snapshot | `{ version, blocks: [{x,y,z,blockId}] }` | **Preserve**: no schema change. New block IDs are backward-compatible (old worlds ignore new IDs; new worlds can place them). |
| Persistence | `castle-academy-world-v1` (blocks), `castle-academy-view-v1` (view state) | **Preserve**: view state already stores visibility/viewMode/section. No block data changes needed. |
| Raycast / collision | `visibleMeshes` filter + `world.get()` nearby-block scan | **Extend**: non-cube models need explicit selection/raycast shape; PlayerController `collides` already uses `world.get()` nearby scan — compatible with new IDs. |
| Layer system | 17 layers covering Y [-32,64), kinds basement/foundation/passage/ground-floor/upper-floor | **Preserve**: new blocks place through existing `layerPlugin.resolveLayerId(y)`. No layer changes needed unless new Y ranges required. |
| Hotbar | 1-7 mapped to `BLOCKS` array index | **Extend**: if new blocks added to `BLOCKS`, hotbar auto-reflects. InventoryPlugin `select()` validates against `BLOCKS`. |

## 8. Catalog ID Mapping: V0.4.2 Proposed → Existing V0.3

**Decision rules:**
- **reuse**: existing V0.3 ID covers the role; new V0.4.2 texture is a visual variant of the same logical block (no new `BlockId`).
- **visual-variant**: same logical role as an existing ID but distinct enough to warrant a separate material/texture under the same ID (handled by material variant, not new block type).
- **new-logical-block**: distinct gameplay/logical role requiring a new `BlockId` added to `BLOCKS` and `VALID_BLOCK_IDS`.
- **defer**: not needed for V0.4 minimum set; postpone to later phase.
- **placeholder**: utility concept, visual-only, no simulation behavior in V0.4.
